# Propuesta Comercial Odoo  
## Cliente Demo: Distribuidora Alfa

## Estado

Borrador interno generado por Autonexus OS.  
No enviar a cliente real sin QA y aprobación de Dirección.

---

# 1. Presentación

Esta propuesta tiene como objetivo acompañar a Distribuidora Alfa en la implementación progresiva de Odoo como sistema de gestión comercial y operativa.

El foco inicial será ordenar clientes, productos, listas de precios, oportunidades comerciales y presupuestos, evitando avanzar sobre facturación o inventario real hasta validar previamente los datos y procesos.

---

# 2. Diagnóstico inicial

Distribuidora Alfa trabaja actualmente con información distribuida en planillas y registros separados. Esto genera dificultades para mantener precios actualizados, evitar productos duplicados, hacer seguimiento comercial y obtener reportes confiables.

Los principales puntos detectados son:

- productos duplicados o mal organizados
- listas de precios con baja trazabilidad
- seguimiento comercial manual
- dificultad para saber el estado de cada cliente
- presupuestos sin circuito claro de control
- reportes comerciales armados de forma manual

---

# 3. Objetivo de implementación

Implementar una primera etapa de Odoo orientada a:

- centralizar clientes
- ordenar productos
- estructurar listas de precios
- mejorar seguimiento comercial
- registrar oportunidades
- generar presupuestos desde un flujo controlado
- preparar una segunda etapa para inventario y facturación

---

# 4. Alcance propuesto por fases

## Fase 1 — Relevamiento y normalización comercial

Incluye:

- revisión del proceso comercial actual
- identificación de tipos de clientes
- análisis de productos y categorías
- revisión inicial de listas de precios
- definición del circuito comercial deseado
- detección de datos duplicados o inconsistentes

## Fase 2 — Configuración comercial base en Odoo

Incluye:

- configuración inicial de empresa
- usuarios y permisos básicos
- carga o importación inicial de contactos
- estructura de productos
- listas de precios
- CRM
- ventas
- presupuestos
- reportes comerciales básicos

## Fase 3 — Validación y pruebas

Incluye:

- pruebas de carga de clientes
- pruebas de productos
- pruebas de presupuestos
- revisión de precios
- revisión de permisos
- ajustes sobre el flujo comercial

## Fase 4 — Capacitación

Incluye:

- capacitación para usuarios comerciales
- uso de CRM
- creación de presupuestos
- consulta de clientes
- consulta de productos
- buenas prácticas de carga y seguimiento

## Fase 5 — Segunda etapa sugerida

Una vez validada la operación comercial, se podrá evaluar:

- inventario
- facturación
- compras
- automatizaciones
- dashboards
- reportes avanzados

---

# 5. Módulos sugeridos para la primera etapa

- Contactos
- CRM
- Ventas
- Productos
- Listas de precios
- Reportes comerciales básicos

No se recomienda iniciar con facturación o inventario real hasta tener validados los datos comerciales, productos, precios y circuito de trabajo.

---

# 6. Entregables esperados

- documento de relevamiento
- estructura inicial de clientes
- estructura inicial de productos
- listas de precios organizadas
- CRM configurado
- flujo de ventas inicial
- pruebas funcionales
- checklist QA
- capacitación inicial
- reporte de cierre de fase

---

# 7. Supuestos

Esta propuesta supone que:

- el cliente compartirá planillas actuales de productos y precios
- el cliente definirá un responsable interno
- los usuarios participarán en pruebas
- los precios serán validados antes de cargarse como definitivos
- la facturación será tratada en una fase posterior
- las definiciones fiscales serán revisadas con asesoría correspondiente

---

# 8. Exclusiones iniciales

No se incluye en esta primera etapa:

- facturación real
- inventario productivo
- integraciones externas
- desarrollos a medida complejos
- limpieza manual extensa de datos
- soporte ilimitado
- decisiones fiscales o contables
- migraciones históricas no relevadas

---

# 9. Riesgos y cuidados

Los principales riesgos son:

- cargar productos duplicados
- usar listas de precios sin validación
- avanzar a facturación sin datos consistentes
- no contar con responsable interno
- capacitar usuarios antes de cerrar el flujo comercial

Por eso se recomienda una implementación progresiva y controlada.
